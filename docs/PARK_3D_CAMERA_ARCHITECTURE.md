# Mayfield Park — three detail levels from one 3D source

This is an implementation specification **and the implementation now used by Park**. The House, Bank and Hotel continue using their earlier 2D art/sprites.

## The three layers

| Layer | Source of truth | Rendered format | Update behavior |
| --- | --- | --- | --- |
| Detail 1 | Existing Park room graph and `actors`, `lights`, `ghosts` states | 2D overhead/overview map with live markers | React state: every simulation update |
| Detail 2 | `Park3DRenderer` fixed perspective camera for each assigned room | **2D PNG** snapshot, produced by offscreen WebGL `canvas.toDataURL()` | On the existing approximately 1.3-second `snapshotActors`/`snapshotFrame` update |
| Detail 3 | The same `Park3DRenderer` 3D geometry and fixed perspective camera | Live WebGL `canvas` with depth, perspective and 3D actor meshes | RequestAnimationFrame; camera fixed, walking poses animate |

**Critical**: Do not create a separate hand-painted background for Detail 2. It must always be a 2D image *derived from the actual Detail 3 source camera for that zone*.

## Current Park cameras and geometry

- `S1`: the timber-roof Park Shelter, picnic tables and lamps.
- `S2`: real 3D playground and swing chains, platforms, slide and surrounding vegetation.
- `T1`: 3D tree with trunk and canopy, bench, path and lamp.
- `F1`, `F2`, `F3`: three soccer-field sectors with 3D goals, turf, perimeter and floodlights. `F2` includes the center circle.

Each camera is **permanently locked** to the fixed eye/lookAt/fov values in `src/park-3d-scene.js` under `PARK_FIXED_CAMERAS`. Movement happens *in front of* the camera; no orbit camera, no third-person tracking, no camera rotations in response to actor movement.

## One engine, no new packages

All geometry is generated by JavaScript inside `src/park-3d-scene.js`, using a WebGL 1 renderer with depth buffering, normals and lighting. It requires no external 3D library and adds no npm dependencies. The source is editable rather than an image of a 3D scene.

The React integration is `src/Park3DView.jsx`:

- `ParkLive3D` renders the selected zone continuously while playing, and freezes the frame when paused. Actors come from the shared live simulation.
- `Park2DSnapshot` builds its *still* image from the same scene and camera and uses the same actors at the scheduled camera snapshot update. The snapshot is a plain PNG data URL shown in an `<img>`.
- In `src/App.jsx`, **only Park** selects the new views; other levels still use `RoomScene`.

The full scene graph remains scene-local while the 2D overview is global. Actor moves from `S1` to `S2` are handled by the Park role scheduler, and the camera renderers update from the same actor `room`, `x`, `kind`, `role`, `color`, `activityState`, and `currentActivity` properties. Capturing a ghost removes its mesh and updates the overview using the same actor state.

## Visual fidelity and constraints

The initial 3D scenes use stylized **low-poly procedural meshes**. They are not high-resolution photorealistic environments; they give true geometric volume and shadows through face shading and perspective. Future level-art improvements should replace/extend these meshes without creating independent static Detail 2 art.

The 3D renderer needs WebGL support in the browser. The current verification container's Chromium software GL initialization failed, so browser pixels were **not** verified here. Source and GPU call tests are provided. A local browser on a machine with WebGL should be used for visual acceptance.

## Validate

```sh
npm install
npm run dev
npm test
```

Open **Park** and click each zone in the overview. Confirm the perspective of each remains fixed while actors move and the tiny 2D feed only changes when the snapshot ticks. `park-3d-renderer-check.html` is a dependency-free renderer smoke-test page served from the project root:

```sh
python3 -m http.server 8080
# http://localhost:8080/park-3d-renderer-check.html
```

The smoke-test page renders one main 3D shelter and all six alternate zone cameras independently of React/Vite, which isolates WebGL failures from application-level issues.
